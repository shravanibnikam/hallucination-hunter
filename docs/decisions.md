# Decisions

- Use a server-only PostgreSQL driver with Supabase's transaction pooler, rather than a browser Supabase client. This allows atomic round creation and locked guess writes.
- Use a system font stack so builds and play never need font downloads.
- Use local PostgreSQL for repeatable database verification. Production uses Supabase Free; no additional hosted services are required.
- The six ordinary samples plus two attention checks form eight CSV rows. Samples are demonstrations, not a validated research dataset.
- Dataset rows require stable UUIDs for safe, repeatable upserts. Omitted optional CSV values use database defaults; importing an existing pair cannot change its content once a round references it (use a new UUID for revisions).
- Pin TypeScript to major version 6 because the current Next.js ESLint parser rejects TypeScript 7. Next.js itself uses the latest stable release.
- Pin ESLint to major version 9; the React plugin currently bundled by eslint-config-next uses APIs removed in ESLint 10.
- Without any attention-check pair, keep the specified N−1 ordinary items and shorten the round by one (up to 9). If the pool is empty, return a friendly 503 rather than creating an empty session.
- The random session UUID is an anonymous bearer capability, kept only in sessionStorage. A minimal GET session endpoint returns progress for refresh recovery; it exposes no item IDs or answer metadata. No cookies are needed.
- Refresh resumes at the next unguessed item; an unsubmitted answer is discarded. The timer restarts on render, while the first served_at stays unchanged. A submitted guess is never rewritten.
- Viewport widths below 768px are recorded as mobile; all others are desktop. This is a coarse screen classification, not user-agent collection.
- Scores and streaks include all round items. Category accuracy, mean confidence, and calibration exclude attention checks. Calibration thresholds use unrounded values; displayed percentages round to the nearest integer. An attention-only round gets an explicit insufficient-data insight.
- Keep all app and share-image color, radius, and type tokens in lib/design-tokens.ts, exposed to Tailwind through CSS variables.
- Shared scores are bounded but self-reported; they never fetch or identify a session. A single next/og image route varies by score and total.
- Nicknames are optional public aliases. Raw research exports are private working files: remove aliases and coarsen timestamps before any anonymized publication. Hosting providers may process operational connection metadata outside the app's study data.
- In-memory limits avoid IP collection entirely: 60 session creations/minute per process, 600 guess requests/minute per process, and 30/minute per session. They reset on cold starts and do not coordinate across Vercel instances; shared global budgets can affect other players. This is a basic abuse brake, not distributed bot prevention. Maps are bounded and expire during requests; no jobs or paid storage are needed.
- Integration tests require a separate database name ending in _test and reset that database's study tables. Playwright uses the same disposable database and real random assignment, retrying session creation until each condition is covered; no production condition override exists.
- A round without an attention check has no failed check, but does not qualify for the leaderboard: eligibility requires an actual correctly answered attention item.
- The reveal highlights the first exact occurrence of fabricated_span. Dataset authors should use an unambiguous span when repeated wording could confuse readers.
- Rounds balance ordinary items by `hallucination_type` before category. The four named types (`wrong_number`, `wrong_entity`, `wrong_date`, `invented_citation`) each get 2 of the 9 ordinary slots and one randomly chosen type gets the extra (3, 2, 2, 2). The one-third category cap is secondary: when the pool cannot satisfy both, the cap rises only as far as type balance requires. `other` pairs fill only slots the four types cannot, and a short type's slots are dealt round-robin to the others. Within these rules the least-shown pair is taken greedily unless it would make the remaining quotas impossible (checked exactly with Hall's condition), so exposure balance is approximate rather than optimal. The type never leaves the server before a guess.
- Single rounds show the fake answer on exactly half of the ordinary items, rounding a 9-item round to 4 or 5 at random per round, at random positions; the attention check is always shown fake. A shorter round with an even count shows exactly half (the six-item sample round shows 3). Paired rounds still place the fake left or right independently per item.
- Repeat play is marked by a random UUID kept in `localStorage` under `hh_device_id` and stored in nullable, indexed `sessions.device_id`. It is created with `crypto.randomUUID()` on first start, replaced if malformed, and sent as null when storage or `randomUUID` is unavailable. It is never returned by any API or shown publicly. Exports add `device_id` and `device_round_number` (1 for the browser's first session by creation time, counting all sessions including pilot and non-study ones; empty without an ID). It identifies a browser profile, not a person: clearing data, another browser, or a private window starts over.
- Every pair stores `real_span`, and `answer_fake` must be `answer_real` with its single occurrence of `real_span` (overlapping matches count as repeats) replaced by a different `fabricated_span`. The importer reports violations by CSV line and `pairs_real_span_check` enforces the same rule. Attention checks are one-span swaps too (for example "four" to "a purple elephant"), so they are not exempt; add an exemption if a future check is built differently. Pairs from before this column cannot be backfilled under the immutability trigger, so the migration deactivates them and adds the constraint `NOT VALID`: those retired rows stay unchecked, while every insert and update is checked and they can never be reactivated without a real span. The samples were re-imported as `sample-v1` under new UUIDs.
- After a guess is stored, the reveal also returns `answerReal` and `realSpan`. When the judged item contained the fake (every paired item, and single items shown fake), the reveal shows the real value beside the fabricated one with minimal styling, pending the reveal redesign. Item responses still carry neither field, nor the hallucination type; pairs retired before real spans existed return a null `realSpan` and show no comparison.
- `STUDY_STATUS` is read per request; only the exact value `open` is study mode, and anything else, including unset, is closed free play. The server sets `sessions.is_study` at creation. Closed `/play` skips consent and the profile and says answers will not be used for research, so `consent_given_at` and `age_confirmed` are nullable, and a check constraint requires both for study sessions. Non-study sessions are excluded like pilots from public totals, the leaderboard, exposure balancing, and default exports (`--include-nonstudy` adds them). `is_pilot` and `is_study` stay separate: a pilot in study mode is `is_study` and `is_pilot`. Sessions from before this change default to non-study, as pre-freeze development data.
- The About page describes every fake as a deliberate change to a real answer, checked against its source, matching the single-span dataset rule; it no longer claims natural model mistakes. The `origin` column remains for a future natural subset, which would need this copy revisited.
- Every exported guess carries its item's `position` in the round (1–10, enforced by the schema) next to `is_pilot`, `is_study`, `device_id`, and `device_round_number`, so position and repeat-play effects can be modeled. A query-level test guards these columns, and CI runs the export both with defaults and with `--include-pilot --include-nonstudy`.
- Exports write every integer column (PostgreSQL `int2`, `int4`, `int8`, found from the query's column types) as pandas nullable `Int64`, built from the raw values, so 8 is written as `8`, not `8.0`, and NULL as an empty field. This covers `final_score`, `best_streak`, `ai_knowledge_rating`, `position`, `response_time_ms`, `confidence`, `total_items`, and `device_round_number`, which is an integer again rather than text.
- Dataset v1, stage 1: the schema does not restrict `category`, so v1 reuses the samples' three (`science`, `geography`, `history`). The 40 candidates per type split 14/13/13 so the final 20 can split 7/7/6, and no topic repeats across the whole set. The candidates were written by Claude (`claude-opus-5-5`) from its own knowledge and are only checked, not sourced, against Wikipedia and Crossref.
- Source checks use the rendered text from the MediaWiki `parse` API, including the infobox but excluding footnote markers and reference lists, and record the revision checked so later stages compare against the same text. A code review found that the first version also matched wikitext, footnote numbers and citation metadata, which let small numbers pass vacuously ("130 ships" for the Spanish Armada matched a footnote; the article gives 141, 137 and 122) and wrongly rejected fakes. Those are now excluded, spaced digit groups count as one number, and stage 1 was rerun. Numbers must match as whole numbers apart from thousands separators and units; rounding does not count, so `21,196` fails against `21,196.18`. Crossref checks the DOI's title, the first author's family name, and the year (off by one is flagged). No contact email is sent to Crossref, which keeps requests in its public pool.
- Candidate rows reuse `import_pairs.validate` by completing each row with a placeholder fake, so the importer stays the single source of the pair rules. Format rules add 25 to 60 words, 1 to 3 sentences (initials and abbreviations such as "S." and "St." do not end a sentence) and a hedge-word list in which only lowercase "may" counts, so the month is allowed. Failing candidates are written to `candidates_v1_failed.csv` with reasons; before the recorded run, three drafts with hedge words were reworded.
- The four v1 attention checks were written by Claude (`claude-opus-5-5`) in a Claude Code session, one per type (none use `other`), with absurd fabricated spans. Like the samples they are single-span swaps, so they meet the real-span rule. HTTP responses are cached under the ignored `research/dataset_generation/.cache/`.
- Dataset v1, stage 2: fakes come from `microsoft/Phi-3-mini-4k-instruct-gguf` (`Phi-3-mini-4k-instruct-q4.gguf`, SHA-256 `8a83c7fb…2edef`, pinned revision), a family outside the Gemma, Llama and Qwen models evaluated later. It runs on CPU through `llama-cpp-python` 0.3.36 (pinned in `research/requirements-generation.txt`; source-only, so installs compile it) with seed 20261101 reset per candidate, temperature 0.7 and 6 threads, and replies are constrained to a JSON schema. The model file and HTTP cache stay out of Git.
- Number fakes must have exactly the real value's shape (each digit position, separators, decimals and unit), which enforces "same unit, formatting and digit count" mechanically; "round" means ending in 0 with no nonzero decimals. Date fakes must be written in the real date's exact format. Entity fakes must resolve to an unambiguous Wikipedia article whose Wikidata item differs from the real one but shares an instance-of (P31) class, which is how "the same kind of thing" is checked without a hand-made taxonomy. Citation fakes must match the real title's case style, subtitle colon and final punctuation, and Crossref must return no work whose title matches.
- Every fake is also rejected if it already appears in the real answer (which would make the pair ambiguous) or anywhere in the stage 1 revision of the source article. DOI-sourced citations have no article text, so the Crossref check stands in. Length outside 0.7 to 1.3 times the real span is a flag, not a rejection. Each completed pair is validated with `import_pairs.validate`, using the real answer as a placeholder `explanation` until selection writes the final one. Every model reply is logged in `fakes_v1_attempts.csv`, and candidates left with no passing fake go to `fakes_v1_failed.csv`.
- The first stage 2 run used generic per-type rules and kept a fake for only 18 of 35 number candidates and 18 of 40 entity candidates (109 of 153 overall). The rejections were correct but showed the model ignoring the rules: places for people ("Edinburgh" for Alexander Fleming), decimals for whole numbers ("79.000000"), and sentences instead of names. The rules were revised once: number prompts give the exact digit pattern (`#,###`), and entity prompts name the kind from Wikidata ("person", "business or public company"). Date and citation prompts were unchanged. The checks themselves were not loosened. A code review then found two check bugs that had also cost fakes: a thousands group starting with 0 (`,098`) read as a leading zero, and footnote numbers counted as article text. With the revised prompts and fixed checks, 126 of 152 candidates have a fake (28 numbers, 25 entities, 39 dates, 34 citations). The date and citation replies matched the first run exactly, which confirms that seeded generation reproduces.
- Dataset v1, stage 3: the artifact check shows exactly half the fakes first rather than flipping a coin per pair, so pairs with no surface difference (same-shape numbers and dates) score exactly 50% instead of whatever share the coin flips gave. The model has no intercept and the features are not centred, so only the features can predict the fake. Accuracy is pooled over 10 stratified folds with a Wilson 95% interval. scikit-learn is pinned at 1.9.1. On the 126 passing candidates it passes (56.3%, CI 47.6-64.7%), but citation fakes are usually shorter than the real titles (26 of 34) and are detectable on their own (74%). That was later fixed by tightening the citation fakes (below) rather than left to the review, and the check will be rerun on the final 80.
- Dataset v1, stage 4: `review_v1.csv` lists alternates as fabricated spans, since each replaces `real_span` the same way as the main fake. The script refuses to overwrite a sheet with review entries. Stage 1 checks only `real_span`, so four subagents fact-checked every other claim in the real answers. Their verdicts are in `claims_v1.csv` and appear as `claim_wrong` or `claim_unverified` flags. They are advisory: nothing is dropped because of them, and the review passes decide (flagged answers were rewritten, below).
- Citation fakes were tightened after the per-type artifact check showed a tell (fakes shorter and missing hyphens). A citation fake must now have exactly the real title's punctuation characters in the same order and a length within 0.85 to 1.15 times the real title's. The prompt gives the title's word count and asks to keep its small words and punctuation while swapping each other word for one of similar length; the model ignored a bare word count, and forcing words through the JSON grammar produced unusable titles. Each citation gets two asks of 3 (seeds 20261101 and 20261102), and the passing title closest in length becomes the main fake. Twelve citation candidates were added (6 science, 6 geography), and 34 of 51 now have a fake. The artifact check now fits a separate model per type as well as one overall, and every interval includes 50%. The review sheet shows `length_diff` on every row.
- Review rows whose answers the fact check flagged were rewritten rather than dropped: the flagged claim is removed or corrected with a fact from the row's own source, and `real_span` is unchanged. Each rewrite is logged in `claims_v1.csv` with the old and new answer and a fresh recheck. Their fakes keep the same model replies: `make_fakes.py --rejudge` re-checks the logged replies against the new answer instead of regenerating, because regenerating a subset does not reproduce the full run's sampling (llama.cpp reuses the previous prompt's cache), and prompts for rewritten rows keep the original answer. Flagged candidates without a fake (the Danube, Pekel 2016 and Mann 1998 rows) were left as they are.
- For margin, 20 `wrong_entity` candidates (10 geography, 10 history) and 8 history `wrong_number` candidates were added and run through every stage with unchanged checks. Three subagents drafted them in parallel and checked them against the repo's own format, source and Wikidata checks. Two drafts used the same Angkor Wat article, which would let one item give the other away, so the geography one was replaced with Nairobi. No source article or span repeats across the 200 candidates.
- Generation-only dependencies live in `research/requirements-generation.txt` (it includes `requirements.txt` and adds `llama-cpp-python`), so CI keeps installing `research/requirements.txt` alone and never compiles llama.cpp. scikit-learn stays in `requirements.txt` because the artifact check and its tests use it. `make_fakes.py` imports `llama_cpp` only inside the generation function, so its checks and `--rejudge` run without it.
- After the two review passes, three types had fewer than 20 kept rows (15 numbers, 17 entities, 4 citations), so 20 more candidates were written for each and run through every stage and both review passes with unchanged checks and the same reviewer instructions (fresh agents per pass). Most earlier rejections were claims the source did not state in so many words: the Crossref record carries no findings or later influence, and many publisher pages returned 403 or a PDF. So the top-up citations state only record fields (authors as recorded, journal, year, volume, pages), and their titles have no punctuation other than a colon, since hyphenated titles rarely got a passing fake. 15 of the 20 citations, 18 of 20 numbers and 16 of 20 entities got a fake; the other five citations failed the unchanged length or punctuation check, and the 20-per-type cap was kept. With the top-ups, 28 numbers, 31 entities, 31 dates and 16 citations are kept, so `invented_citation` stays below 20. The artifact check on all 195 rows with a fake still passes overall and per type.
- No human reviewed the rows. The review was done by two independent AI passes, each source-quoted, with rows kept only on agreement. For each type, pass A and pass B were separate Claude subagents (`claude-opus-5-5`) with the same instructions, and neither could see the other's verdicts. Each pass quoted the source sentence (the stage 1 Wikipedia revision, or the Crossref record and publisher page for citations) for every claim in the real answer, failed any claim without a quote, rejected figures the source gives more than one way and fakes that are implausible, not definitely false or patterned, chose an alternate when only it passed, and chose `no` when in doubt. Both passes are saved with their quotes and reasons in `review_v1_passes.csv`, and every Wikipedia quote was matched against the cached article text (1,033 of 1,034 word for word; the one paraphrase is on a row both passes rejected). `finalize.py combine` keeps a row only when both passes made the same keep decision; every disagreement becomes `no`. The passes agreed on 179 of 195 rows (92%) and kept 106. The About page now says the fakes were "checked against their sources" instead of "checked by hand".
- After the first top-up was reported, Shravani approved a second round of 20 citations (7 science, 8 geography, 5 history) was added under the same design and unchanged checks: titles of 25 to 80 characters with no punctuation other than a colon, and answers that state only Crossref record fields. 19 got a fake (one failed the length and punctuation checks); fresh pass A and pass B agents with the same instructions agreed on 16 and kept 14, so `invented_citation` has 30 kept rows. Because `make_review.py` refuses to overwrite a filled sheet, the filled sheet was moved aside, the sheet regenerated with the new rows, and `finalize.py combine` rebuilt every `keep` from `review_v1_passes.csv`; all 195 earlier rows came back unchanged. The artifact check on all 214 rows with a fake still passes overall and per type. Across both rounds the passes agreed on 196 of 214 rows (92%) and kept 120.
- Dataset v1 is frozen: `research/data/pairs_v1.csv`, SHA-256 `e5bf5fbfb80f88ad7348ff293240fdf5b3b5854eaffb0d179a43a603dd19c9d6`, 84 rows (80 pairs, 20 per type split 7/7/6 across science, geography and history, plus the 4 attention checks), all `dataset_version` `v1` with stage 1 UUIDs. `finalize.py` validates the review sheet reading only `id`, `keep` and `notes`, draws rows at random with seed 20261103 (every kept row has a combine note, so the empty-notes preference had no effect), uses the chosen alternate where `keep` is `alt2` or `alt3` (7 rows), and keeps 8 of 20 citation fakes longer than the real title. For `wrong_date`, geography and history tied for fewest kept rows (10 each); the tie went to geography, the earlier category. Explanations name the real value and its source in at most 30 words, with `real_span` once and no new number or date, and a test enforces this. Where an article is titled with the answer itself, the explanation reads "The correct answer is X, as Wikipedia's article on the subject confirms." The final artifact check skips attention checks and passes overall (46.3%, CI 35.7-57.1%) and per type (numbers 50.0%, the other three 40.0%, every CI including 50%), so no swaps were made. The import dry-run against a throwaway local database found 84 valid rows and 0 invalid, and a throwaway import also passed the schema's constraints. A 1,000-round simulation per condition on the real pool confirms type balance (2 or 3 per type), the single-condition split (4 or 5 fakes of 9) and the category cap (at most 3).
- Hallucination Hunter is run as an independent project by Shravani, not through any university, so there is no IRB or faculty advisor. The site says so on the consent screen and the About page, and names no institution anywhere. Consent is explicit about release: the consent text says the anonymized responses will be released publicly with the findings, and the consent checkbox reads "I agree to take part and to the public release of my anonymized responses". The privacy page commits to removing nicknames and coarsening precise timestamps before release; the export stays raw working data, and that anonymization belongs in the release step. The study contact is the single constant `STUDY_CONTACT` in `lib/constants.ts`, which must be a personal, non-university address; until it is set, both pages mark it as a placeholder. Recruiting uses personal channels only, and results go to venues that do not require IRB review (arXiv, Hugging Face, the findings page).
- The end screen shows two small charts. By category, the player's accuracy sits beside the average player's. That average comes from other completed study rounds: pilot rounds, rounds that failed the attention check, attention items and too-fast guesses are left out, and so is the player's own round. It is withheld until at least `MIN_COMPARISON_PLAYERS` (20) other players contributed to a category, so an early average never describes one person. The gut-check chart puts accuracy at each confidence level next to the score a well-calibrated player would have at that level (50% to 100%, the same mapping as the calibration message). Both are plain HTML/CSS with no chart library. Every value is printed as text, and each confidence column is focusable with its full reading as its accessible name. The comparison shows only after a round is finished, so it cannot influence that round's judgments.
- The landing page plays one worked example of the reveal: "How many hearts does an octopus have?", with "five" highlighted, struck and replaced by "three". The fact is deliberately not in any candidate or study pair, so the page gives nothing away, and the card is labelled "Example · not part of the study". It plays once (about 3.5 seconds) and then rests on the result, with a replay button, so it stays under the five-second limit for auto-playing motion (WCAG 2.2.2) and under reduced motion shows only the final state. It replaces the static mock-answer art, which was hidden on narrow screens; the demo shows at every width. The reveal's highlighter now keeps the fake text in the ink colour until the highlight passes over it.
- The share image is a poster: the score as a large accent number (or the question when there is no score), the landing page's octopus example as a tilted reveal card, the radar rings, and "Play at" the `APP_URL` host. It uses the built-in OG font, so the bundle stays small but has no bold weight; a bundled `ttf` would add true bold if wanted. It still shows only the self-reported score and round length.
